Engagement Overview

Full VAPT retest for a leading investment holding company. This was not a checkbox rescan — every baseline finding from November 2025 was independently re-verified with timestamped evidence and technical corroboration, not client attestation. Dual scope: external web/cloud attack surface (7 systems) and internal infrastructure (101 hosts, flat /24 network). Testing window: 13–16 July 2026 (4 business days + evidence packaging on Day 5).

All evidence captured with cryptographic chain of custody: script -f -t + ts '%Y-%m-%d %H:%M:%.S' + SHA256 hashing on every log file and terminal session.

Day 1 — Scope Validation & Network Reconnaissance

Host Discovery & Inventory

101 hosts confirmed online across the /24 flat network. Key infrastructure discovered:

  • Sophos Gateway — Perimeter firewall (stateful, no WAF rules on office traffic)
  • Ubiquiti APs — Multiple wireless access points, no VLAN enforcement between 2.4GHz/5GHz
  • Hikvision CCTV Infrastructure — 8 cameras, NVR on same subnet as AD/BYOD
  • Biometric Access Control — Door lock readers, ARP-visible, unsegmented
  • 33 Intel Workstations — Domain-joined, Windows 10/11 mixed patch levels
  • 10 AzureWave Mobile Devices — MDM enrolled but WiFi SSID unencrypted for guest
Network Design Finding: Flat /24 with no VLAN segmentation between corporate AD (192.168.0.0/25), IoT/cameras (192.168.0.128/26), and guest BYOD (192.168.0.192/26). No 802.1X enforcement. Result: Compromised BYOD device could pivot to CCTV, then lateral move to AD via crafted Kerberos Pre-Auth packets.

DNS & External Resolution Mapping

Dual DNS Architecture Documented:

  • Internal DC (192.168.0.6) — Authoritative for company.local and external domain company.ng
  • External Resolvers
    • — Public A records point to corporate /24 gateway IP (203.0.113.50)

Implication: DNS rebinding attack surface confirmed. Internal resolver returns RFC1918; external resolver returns routable IP. Not directly exploitable in this engagement but documented for CSO briefing.

Email Security Retest (Split-Brain DNS)

Issue: Internal nslookup showed SPF/DKIM/DMARC missing at 10:58 WAT.

Corroboration (External Validators): Queried via 8.8.8.8 and 1.1.1.1 at 11:31–11:32 WAT:

$ dig @8.8.8.8 company.ng TXT | grep v=spf1 company.ng. 3600 IN TXT "v=spf1 include:spf.protection.outlook.com -all" Response time: 271ms $ dig @8.8.8.8 _dmarc.company.ng TXT _dmarc.company.ng. 3600 IN TXT "v=DMARC1; p=quarantine; rua=..." Response time: 315ms $ dig @8.8.8.8 selector1._domainkey.company.ng CNAME selector1._domainkey.company.ng. 3600 IN CNAME selector1-company-ng._domainkey.protection.outlook.com. Response time: 591ms ✓ Valid RSA-2048 DKIM key present
Conclusion: Email authentication is properly configured externally. Internal DC showing null records is classic split-brain DNS misconfiguration (internal zone not synced to external DNS provider). Medium finding: Client must update internal zone or remove redundant NS record from DC.

Rogue Server (192.168.0.50 — FILESERVER): Windows Server 2012 R2 — VULNERABLE

$ nmap -p 445 --script smb2-security-mode 192.168.0.50 | smb2-security-mode: | Message signing: False ← VULNERABLE | SMBv1: Enabled ← DEPRECATED | Null Authentication: Enabled ← EXPOSED | Timestamp (11:50:23 WAT): ALLOW_UNAUTHENTICATED
HIGH SEVERITY: FILESERVER (Windows Server 2012 R2 EOL) allows SMBv1 null-authenticated access.
Impact: Arbitrary file read/write as NT AUTHORITY\ANONYMOUS. Active user sessions present on share.
Remediation: Upgrade to Server 2022 + enforce SMB 3.1.1; disable SMBv1.
